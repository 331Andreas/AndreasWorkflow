# 诉讼案件材料梳理工作流

> 为诉讼律师设计的 Obsidian 知识管理框架。以标准化文件夹结构为骨架，以可扩展的 Skill 模块为引擎，将散乱的案件材料收归一处，使案情脉络清晰可循。

这是 **AIuris 法随**发布的第一个开源工作流模板。它不是一个功能堆砌的工具，而是一套经过实践打磨的**案件知识管理框架**——你可以按需加载模块，也可以裁剪至最简，框架本身保持稳定。

后续法随将持续发布更多面向律师的模块化工作流与 Skill，本项目是这一体系的起点。

---

## 项目简介

这是一个面向诉讼律师的 **Obsidian 案件管理模板库**。它将散乱的案件材料组织为结构化知识库，配合多个可扩展的 Skill 模块，覆盖从收料到归档的完整工作流。

**核心理念：** 每个案件 = 一个标准化文件夹，配以可视化图表和自动化工具，让你快速把握案情、高效产出文书。

---

## 功能特性

- **三阶段工作流**：材料接收 → 案件建档 → 文件归档，每个阶段有明确产出
- **7 层标准化文件夹**：从证据原件到诉讼文书，统一的目录结构
- **Mermaid 可视化四图**：案件大事记、法律关系图、诉讼流程图、诉讼时效甘特图
- **5 个可扩展 Skill**：模块化技能，按需调用，支持自由扩展
- **Dataview 联动**：案件概览页一键跳转关联文档
- **材料格式转换**：PDF/图片/Word/Excel 等任意文件 → Markdown（OCR 支持）
- **8 类法律文书模板**：起诉状、答辩状、律师函、合同等，格式规范内置

## 系统架构

```
工作流模板/                       ← Obsidian Vault 根目录
├── README.md                    ← 本文件
├── SETUP.md                     ← 环境检查清单（首次使用必读）
├── 提示词.md                    ← 核心规范（P0/P1 纪律 + Skill 索引）
├── skills/                      ← 技能模块（可扩展）
│   ├── project-init_SKILL.md
│   ├── litigation-analyst_SKILL.md
│   ├── markitdown_SKILL.md
│   ├── legal-document-generator_SKILL.md
│   └── legal-litigation-viz_SKILL.md
├── 模板库/                      ← 案件概览模板
├── 01_规范文档/                 ← 文件管理规范
├── 案件库/                      ← 所有案件（每个案件一个文件夹）
├── 法律法规库/                  ← 本地法条引用库
├── 收料库/                      ← 新接收材料的临时入口
└── 工作日志/                    ← 工作记录
```

## Skill 索引

| Skill                        | 触发条件      | 职责                            |
| ---------------------------- | --------- | ----------------------------- |
| **project-init**             | 每次会话开始    | 读取规范 + 模板 + 环境检查              |
| **litigation-analyst**       | 案件管理相关    | 三阶段工作流调度、文件夹结构、frontmatter 格式 |
| **markitdown**               | 收料 / 文件转换 | 任意文件 → Markdown（含 OCR）        |
| **legal-document-generator** | 起草文书      | 8 类文书生成、格式规范、法条引用             |
| **legal-litigation-viz**     | 可视化 / 时间轴 | Mermaid 四图、HTML 时间轴、A4 打印     |

### 添加新 Skill

1. 在 `skills/` 下新建 `{skill名}_SKILL.md`
2. 在 `提示词.md` 的 Skill 索引表中添加一行
3. 在 Skill 文件中声明与现有 Skill 的互补关系

Skill 之间通过 YAML frontmatter 声明职责边界，互不重叠。

## 案件文件夹结构

每个案件在 `案件库/` 下以 `{案件名}_{年度}/` 命名，内部固定 7 层：

```
案件库/中联建工诉瑞安置业建设工程施工合同纠纷_2025/
├── 案件概览.md                  ← 案件仪表盘（frontmatter + Dataview）
├── 01_材料原件/                 ← 证据材料（合同、收据、报告等）
├── 02_材料清单.md               ← 材料索引表
├── 03_案件信息.md               ← 案件详情（含 Mermaid 图表）
├── 04_法条检索/                 ← 相关法律条文
├── 05_案例检索/                 ← 参考判例
├── 06_检索报告/                 ← 分析报告、法条报告、案例报告
├── 07_诉讼文书/                 ← 起诉状、答辩状、证据目录
├── 08_庭审材料/                 ← 传票、开庭通知（可选）
└── 09_结案材料/                 ← 判决、裁定、调解书（可选）
```

## 快速开始

### 1. 环境准备

在 Obsidian 中打开本项目文件夹作为 Vault。

**必备插件：**
- 核心插件：Properties（属性）
- 社区插件：Dataview

Python 环境（仅 markitdown skill 需要）：
```bash
pip install "markitdown[all]"
```

详细环境检查见 [`SETUP.md`](./SETUP.md)。

### 2. 新建案件

复制 `模板库/案件概览模板.md` 到 `案件库/{案件名}_{年度}/`，替换占位符 `{案件名}` 和 `{年度}`。

### 3. 日常工作流

```
收料 → 放收料库 → markitdown 转 Markdown → litigation-analyst 建档 → 归档到案件
```

每个 Skill 有独立的工作流说明，按需调用。

## ⚠️ 重要声明

### 模拟数据

本项目包含的 5 个示例案件**全部为模拟数据**：

- 所有当事人名称、案号、法院、法官、事实均为虚构
- 参考案例的案号和裁判内容不指向任何真实判例
- 证据材料（合同、检测报告、付款记录等）均为示例内容
- **仅供学习框架使用，不构成任何法律建议**

每个模拟文件内部均已标注 `⚠️ 模拟数据，仅供演示`。

### 使用须知

- 本项目是**框架模板**，不包含法律咨询功能
- 法律法规库仅含少量节选条文，**实际使用时须自行补充完整法条**
- 所有引用须以官方发布的法律文本为准
